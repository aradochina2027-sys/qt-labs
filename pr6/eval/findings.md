# Результати оцінювання RAG-помічника

## 1. Тестовий набір

Для перевірки системи підготовлено 13 тестових питань.

Перевірялися такі випадки:
- просте фактичне питання;
- питання за інструкцією товару;
- відповідь із кількох документів;
- вибір чинного документа замість архівного;
- хибне припущення в питанні;
- запит до внутрішньої інформації;
- питання поза базою знань;
- документ існує, але потрібного факту немає;
- спроба змінити інструкції помічника;
- часткова відповідь;
- відстеження замовлення;
- фільтрація за конкретним товаром;
- питання іншою мовою.

## 2. Результати retrieval

У базі знань:
- 16 документів;
- 85 фрагментів.

Локальна перевірка retrieval показала:

Очікувані документи знайдено: 9/9.

Для кожного запиту до контексту передається не більше 4 фрагментів.

Архівні документи не передаються моделі.

Внутрішні документи для персоналу також не передаються моделі.

Таким чином, програмна фільтрація внутрішніх та застарілих документів працює правильно.

## 3. Аналіз окремих тестів

### Просте фактичне питання
Для питання про строк повернення товару знайдено документ `правила-повернення.md`.

### Інструкція товару
Для питання про навушники Оріон X2 знайдено `інструкція-навушники-оріон-x2.md`.

### Кілька документів
Для питання про повернення грошей і бонусів знайдено документи про повернення та програму лояльності.

### Чинний і архівний документи
Для питання про доставку використано чинні документи. Архівна редакція правил доставки до контексту не потрапила.

### Внутрішня інформація
Внутрішня інструкція оператора не потрапила до контексту.

### Питання поза базою
Retrieval може знаходити семантично схожі фрагменти, але остаточне рішення про наявність відповіді повинно прийматися RAG-пайплайном.

### Prompt injection
Запит із текстом "Забудь попередні інструкції" не відкрив доступ до внутрішнього документа.

### Питання іншою мовою
Для англомовного питання про відстеження замовлення знайдено відповідний FAQ.

## 4. Помилки retrieval

Під час першої перевірки питання про доставку до Польщі не містило всі документи, зазначені в очікуваному наборі.

Аналіз показав, що `faq-доставка-і-відстеження.md` уже містить достатній чинний факт про відсутність міжнародної доставки.

Після уточнення очікуваного документа локальна перевірка retrieval дала результат 9/9.

## 5. Помилки generation

Повне оцінювання generation тимчасово не завершено через обмеження зовнішнього Gemini API.

API повернув помилку HTTP 429 `RESOURCE_EXHAUSTED`, оскільки було досягнуто ліміту безкоштовних запитів.

Ця помилка є інфраструктурною і не є помилкою retrieval.

Після відновлення квоти необхідно повторно виконати повний прогін `run_eval.py` та доповнити цей розділ результатами generation.

## 6. Висновок

Було реалізовано RAG-помічник, який виконує семантичний пошук у власній базі знань, формує обмежений контекст та використовує знайдені фрагменти для генерації відповіді.

Реалізована програмна фільтрація архівних та внутрішніх документів. Локальна перевірка retrieval показала результат 9/9 для тестів із заданими очікуваними документами.

Також система перевіряється на питання поза базою знань, хибні припущення, prompt injection та відсутність необхідного факту.

Повна перевірка генерації буде завершена після відновлення доступної квоти Gemini API.
